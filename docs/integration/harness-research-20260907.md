## Framework choice and replay safety

Mastra fits Hades' TypeScript/Node sidecar and avoids a Python process boundary for ordinary tasks. Its durable workflows, suspension, approval handling and subagent hooks are useful integration points. Pin an actual stable package and validate it: the inspected main revision is `62da1b231af65b86a367fb221d8a183bbecea6c8`, whose core package is an alpha, while separately retained registry metadata identified stable `@mastra/core@1.64.0`. Findings about main do not prove the stable package behaves identically. [Source and package decision](../../.research/20260907-harness-comparison/mastra-decision/decision.md)

Neither framework removes the effect-replay problem. Mastra explicitly warns that recovery can repeat model calls and tool execution. Its inspected implementation can acquire a recovery lease, but falls back to a no-op provider when none is configured; the guide also contains an older contradictory statement that distributed leases are absent. Persistent storage alone is insufficient. [Recovery guide](https://github.com/mastra-ai/mastra/blob/62da1b231af65b86a367fb221d8a183bbecea6c8/docs/src/content/en/docs/harness/durable-agents.mdx), [lease implementation](https://github.com/mastra-ai/mastra/blob/62da1b231af65b86a367fb221d8a183bbecea6c8/packages/core/src/agent/durable/durable-agent.ts)

Pydantic's Temporal option is durable only inside a workflow started on an actual worker/service. Its separate Harness package offers a valuable distinction: settled continuation snapshots versus interrupted tool effects whose outcome is unknown after a crash. Adopt that distinction regardless of the framework. [Temporal requirements](https://github.com/pydantic/pydantic-ai/blob/fe49041fb9ed46eb964574e14dfda20aa87f61ad/docs/durable_execution/temporal.md), [step persistence](https://github.com/pydantic/pydantic-ai-harness/blob/d004ad6a308c0cc88efc7b1b4b3913147e794424/pydantic_ai_harness/step_persistence/README.md)

## Delegation, scheduling, heartbeats and hooks

The retained docs.x.ai Grok Bot pages describe asynchronous peer messages that wake recipients, user steering with priority over background work, and routines triggered by schedules or events. They describe cloud execution with desktop/mobile clients. **These are vendor-document claims, not inspected proprietary internals.** Fresh plain HTTPS requests reproduce the same cross-brand docs bodies. The official x.ai launch page also links Cursor-hosted downloads and names Cursor plans, corroborating the presentation across first-party pages. This still does not establish corporate ownership, the reason for the branding, or private architecture. [Official launch](https://x.ai/news/introducing-grok-bot) No source inspected establishes a private heartbeat frequency, queue schema, lease duration or delivery guarantee. [Collaboration](https://docs.x.ai/grok-bot/chat-and-collaboration), [routines](https://docs.x.ai/grok-bot/skills-routines-and-automations), [architecture](https://docs.x.ai/grok-bot/teams-and-enterprises)

For Hades, converge peer messages, schedules, supported webhooks and explicit continuations on one durable wake queue. This is our recommended design:

- Persist the validated inbound event and wake record before acknowledging delivery. Deduplicate by source event ID and reject changed payloads under a reused key.
- Claim work transactionally with an owner, expiry and increasing fence. Reject checkpoints or completion from an expired owner. A reconciler recovers committed but unnotified work.
- Distinguish a **lease heartbeat** that renews ownership, a **routine heartbeat** that schedules reassessment, and a connection keepalive. They serve different purposes.
- Carry parent/child lineage, room membership, project access, budgets, cancellation and reply correlation into every delegated run. Bound hops, fanout and repeated peer wakeups.
- Journal tool start and terminal receipt. Reconcile ambiguous external effects before replay; use idempotency keys where a provider supports them.

Rakazo supplies concrete transaction, replay-key, handoff and lease patterns worth adapting to the existing Hades team service. Its replay path does not compare changed payloads or recheck all permissions before returning; its pre-read fence calculation is not proof of an atomic monotonic claim. Hades must bind replay identity to immutable payload/authority, return stored results and test transactional fencing rather than copying these guarantees by assumption. A chat transcript or agent display name is not an authenticated bot identity or task queue. [Pinned peer delivery implementation](https://github.com/elie222/rakazo/blob/8bd5e34a9b3b12dd1829026f7dabcde444a14268/packages/adapters/src/bot-messages.ts), [lane findings](../../.research/20260907-harness-comparison/rakazo-runtime-sources/REPORT.md)

Always-on execution requires an available local service or selected remote worker. A desktop timer cannot run a sleeping or powered-off laptop. Show execution location, availability, next run and failed/paused state honestly.

## LongHorizon and browser integration

LongHorizon's useful contribution is a bounded manager/executor/auditor process with restored task state, durable steering commands and a completion branch gated by the latest auditor report. Apply the completion principle to Hades artifacts and tests; its parsed auditor-report fields do not themselves establish artifact correctness. The inspected prompt builder caps selected audit/feedback history, while task, contract and current-state text are separately interpolated; this is not a whole-request token bound. The reviewed WebSocket heartbeat is connection health, not an agent scheduler. Benchmark gains and long-duration claims were not reproduced. [Manager implementation](https://github.com/AMAP-ML/LongHorizon-Harness/blob/a1dd930614972b92361c1b9cd6aac441a6db5a65/src/lh_harness/manager.py), [wake/browser report](../../.research/20260907-harness-comparison/wake-browser-sources/REPORT.md)

Stagehand main at `d4f16a98a5061279bed997b98fd3f0c17334eedb` is a v4 browser SDK using extension/CDP primitives. Integrate its observe, act and schema extraction through Hades' browser provider boundary, with explicit browser ownership, allowed origins, download roots, cancellation and post-action evidence. Older `stagehand.agent()` examples do not match the inspected SDK class. Explicit close of a connected local browser handle sends `Browser.close`; `keepAlive` failure cleanup is not a detach-only promise. Hades must distinguish closing a Stagehand instance, detaching a borrowed browser and terminating an owned browser. Package metadata at this revision identifies version 4.0.2. Explicitly closing a connected local browser handle can terminate the borrowed browser; closing the Stagehand RPC context is a different operation. Preserve user-owned browser lifetime and test detach versus terminate before enabling this adapter. Stagehand browser control does not supply macOS Accessibility or arbitrary native app control. [Current SDK](https://github.com/browserbase/stagehand/blob/d4f16a98a5061279bed997b98fd3f0c17334eedb/packages/sdk-ts/src/stagehand.ts), [browser factories](https://github.com/browserbase/stagehand/blob/d4f16a98a5061279bed997b98fd3f0c17334eedb/packages/sdk-ts/src/browser/factories.ts)

## Context and token management

Keep the complete run/effect journal durable and construct a smaller working context from it. Store authoritative task requirements, corrections, permission decisions, pending effects and acceptance results outside generated summaries. Summaries may shorten evidence; they cannot grant approval or mark an unverified task complete.

Use cheap reductions first: artifact handles for large outputs, bounded relevant excerpts, deduplicated unchanged file reads and clearing older settled results while preserving tool-call/result pairing. Then summarize older settled ranges, preserving source IDs/hashes and a recent tail. Validate the summary before atomically replacing the working-view pointer. Failed compaction must leave the prior state usable. Pydantic Harness documents this staged approach; the pinned Letta code offers additional TypeScript cut-point and overflow-retry patterns. The inspected `letta` revision is a landing page, so the executable reference was its linked `letta-code` repository. [Pydantic compaction](https://github.com/pydantic/pydantic-ai-harness/blob/d004ad6a308c0cc88efc7b1b4b3913147e794424/pydantic_ai_harness/compaction/README.md), [Letta compaction](https://github.com/letta-ai/letta-code/blob/701f2a5367828847313876c735ade27b9df97689/src/backend/local/compaction.ts)

Budget the full request, including system state, tool schemas, images and reserved output. Prefer provider counting or the matching tokenizer; otherwise label estimates and anchor them on measured usage. Keep cumulative run spend separate from context occupancy. Use high/low thresholds and minimum reclaimed context to avoid excessive summarization and cache churn. Pydantic explicitly warns that clearing/deduplication invalidates prompt cache from the edit point. Measure cache writes, summarization usage, retries and task quality together; smaller context does not automatically mean lower total cost. Clearing or deduplicating earlier messages can invalidate cached prefixes; count that cost before claiming a net token or cost improvement.

Provider-native compaction belongs inside typed adapters: OpenAI compacted output contains state that must be carried forward intact, while Claude requires compaction-iteration usage to be counted separately. Preserve portable Hades state for provider switches. These public APIs do not reveal private ChatGPT Work or Claude Cowork context-selection algorithms. [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction), [Claude compaction](https://platform.claude.com/docs/en/build-with-claude/compaction)

LLMLingua should start as an optional experiment on retrieved prose. Its local compressor adds runtime and latency, and tokenizer-dependent targets do not guarantee exact limits or semantic retention. Evaluate numbers, negations, citations and final task accuracy, including compression overhead. Do not compress approvals, pending tool arguments or authoritative task state with it. [Compressor implementation](https://github.com/microsoft/LLMLingua/blob/e0e9d99beb94098bbd924aa53c2c112eac41c758/llmlingua/prompt_compressor.py)

## Hermes gaps, supporting components and acceptance

At historical Hades baseline `fbce2ae52c8010a07b3e3cd7093254784c33ef57`, the inspected native route used workspace/MCP tools, a twenty-step setting and ten-message conversation history. Intermediate execution history was not a durable continuation checkpoint. Separate CLI/swarm features should become available through one effective-capability registry, with real native-route tests. Hermes has computer-use interfaces, delegation and context-compression machinery; its inspected permission helper also contains a sanitizer-failure fallback to the full environment that Hades should not copy. Selected-source inspection does not establish complete parity or superiority. Concurrent Hades fixes after this snapshot require separate acceptance. [Hermes comparison](../../.research/20260907-harness-comparison/hermes-sources/FINDINGS.md)

vLLM is an inference-server integration, not an orchestration framework; Ink is a terminal renderer, not a replacement desktop. Current vLLM evidence includes experimental macOS CPU support, so claiming it cannot run on a Mac would be inaccurate. Autoreason suggests iterative candidate/judge experiments. The inspected Autoreason tree had no license grant, and self-evolution's README asserted MIT without a retained license file: do not copy their implementation until reuse rights are resolved. Preserve notices for permitted reuse. Mastra `ee/` files carry separate restrictions and must not be bundled under an assumed Apache grant. [Component/license report](../../.research/20260907-harness-comparison/rakazo-runtime-sources/REPORT.md), [Mastra license map](https://github.com/mastra-ai/mastra/blob/62da1b231af65b86a367fb221d8a183bbecea6c8/LICENSE.md)

Before calling this integration complete, verify a real multi-file task across forced context refresh and worker restart; ambiguous write recovery; two competing lease owners; persisted approval and denial; cancellation beating stale completion; duplicate webhook/peer deliveries; bounded schedules and catch-up; and a two-agent dependent workflow with independently checked artifacts. Validate Codex subscription, OpenRouter and local inference separately. Native visual/computer-use acceptance and upstream benchmarks remain separate gates.
